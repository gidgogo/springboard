# 시연 영상 · 숏폼 만들기

## 1. 시연 영상 (가산점, 접수양식 7번)

인정 범위: **목업 · 프로토타입 · 화면 녹화**. 가장 설득력 있는 건 **Pleos 에뮬레이터에서 실제로 동작하는 화면 녹화**다.

### 구성 (60~90초)

| 구간 | 화면 | 자막·내레이션 |
|---|---|---|
| 0~5초 | 제목 + 한 줄 소개 | 앱 이름, 한 문장 |
| 5~15초 | **불편한 장면** (짧은 실사·일러스트·텍스트) | "누가, 언제, 무엇이 불편한가" |
| 15~45초 | **에뮬레이터 화면**: 주차 → 기어 D(주행 화면 자동 전환) → 차량 이벤트 → 음성 안내·응답 | "차가 먼저 알려 줍니다", "화면을 보지 않아도 됩니다" |
| 45~60초 | 정차(P) → 상세 화면 | "정차하면 자세히" |
| 60~75초 | 쓰는 SDK 한 장 요약 (Vehicle · NaviHelper · TTS/STT · Gleo) | 기술 활용성 |
| 75~90초 | 기대 효과·확대 계획 한 줄, 마무리 | 사업성 |

### 촬영 방법

```bash
adb exec-out screenrecord --output-format=h264 - > demo.h264        # Ctrl+C 로 종료
ffmpeg -framerate 60 -i demo.h264 -c copy demo.mp4
```

- Virtual Console 조작 화면은 PC 화면 녹화(OBS 등)로 따로 찍어 나란히 배치하면 "차 신호 → 앱 반응"이 잘 보인다.
- 음성이 녹화에 담기는지 미리 확인 (에뮬레이터 소리는 PC 오디오로 녹음).
- 16:9 가로, 자막은 크게(차량 화면 글씨가 작게 보일 수 있음).
- 시연 대본([testing-and-demo.md](../04-dev/testing-and-demo.md) 5절)과 같은 순서로 찍으면 PT 준비가 함께 된다.

### 내보내기 전 (블라인드)

```bash
ffmpeg -i demo.mp4 -map_metadata -1 -c copy demo_clean.mp4     # 작성자·장치 메타데이터 제거
```

- 얼굴·목소리·이름·학교·계정명이 나오지 않게. 내레이션은 TTS로 대신할 수 있다.
- 배경 음악·이미지는 **저작권 확인된 것만** (제3자 권리 침해는 수상 취소·상금 환수).
- 링크로 낼 때: 로그인 없이 열리고, 채널·계정 이름에 실명이 없는 곳. 생성형 AI 영상 도구를 쓸 경우 그 서비스의 공유 링크는 쓰지 않는다.

## 2. 숏폼 챌린지 (선택, 숏폼상 50만 원 + 행사 초청)

| 규칙 | 내용 |
|---|---|
| 길이·방향 | 30초~1분, **세로** |
| 올릴 곳 | 본인/팀 계정 Instagram 릴스 또는 YouTube Shorts (팀 계정 권장) |
| 해시태그 | 2~3개, **`#HMG차량용앱개발공모전` 필수** (제안: `#PleosAppMarket` `#HMG앱공모전`) |
| 기간 | 10-21 ~ 11-15 |
| 제출 | 링크를 접수양식 8번에 |

구성 예시 — **Spot → Solve → Scene**
1. **Spot** (0~10초): 불편한 순간 하나. 공감되는 상황.
2. **Solve** (10~35초): 앱이 차 신호로 해결하는 장면. 실제 앱 화면을 3~4초 꽉 차게.
3. **Scene** (35~60초): 해결된 뒤의 모습, 앱 이름.

- 가로 시연 영상을 가운데만 자르면 화면이 잘린다 → 세로용으로 따로 편집.
- 실제 앱 화면이 들어가면 기획서와 연결된다.
