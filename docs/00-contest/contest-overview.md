## 3. 심사 기준

### 1차 (서류) — 세부 배점 비공개

| 항목 | 보는 것 | 우리가 보여줄 것 |
|---|---|---|
| **차량특화성** | 모바일 대비 차량 환경만의 독자적 가치·우위. 주행·정차 맥락과 차량 기능의 유기적 결합 | "폰으로도 되는데?"에 답할 수 있는 핵심 기능. 차량 데이터 없이는 성립하지 않는 구조 |
| **창의성** | 기존에 없던 아이디어. 운전자·동승자의 Pain Point와 Needs를 명확히 정의하고 해결 | 구체적인 한 장면(누가·언제·어디서)과 그 장면에 딱 맞는 해결 |
| **기술 활용성** | Pleos Playground SDK·API를 **핵심 기능과 사용 경험**에 적절히 활용 | "어떤 SDK의 어떤 API로 어떤 기능" 표. 장식이 아닌 핵심에 사용 |
| **사업성** | 타깃 고객, 사용자 확보·지속 이용·확대 가능성 (**타깃 분석, 예상 MAU, Retention Rate, 확대 계획**) | 숫자와 근거(산식). [business-metrics.md](../01-plan/business-metrics.md) |
| [가산점] 개발 산출물 | 시연 영상(화면 녹화 포함), GitHub(소스+APK) — **제출 수준에 따라 단계별 가산점** | 11-15까지 동작하는 최소 기능 + 영상 + GitHub(release APK) |

### 2차 (PT, 12-03~04)

- **실제로 동작하는 앱 시연 필수** (Pleos Connect Emulator 구동 화면 또는 실기기).
- 세부 기준은 추후 공지 → 공지사항 수시 확인.
- **수상 여부와 순위는 2차 PT에서 제출·시연한 결과물로 확정**. PT 이후 추가 개발은 순위에 영향 없음.
- 1차 제출물은 PT 전까지 자유롭게 고도화 가능.

## 6. GitHub 제출 규칙

- 소스 코드와 APK를 **한 저장소**에. APK는 **`apk/` 폴더**에.
- 파일명: **`팀명_앱이름_release.apk`**, **실행 가능한 release 빌드**.
- 용량이 커서 올라가지 않으면 GitHub **Releases**에 올리고 Release 페이지 주소를 제출.
- **README.md 필수 항목** (이 저장소 README 맨 위에 자리를 만들어 둠):
  1. 앱 이름 및 한 줄 소개
  2. 실행 방법
  3. 테스트 환경 및 필요한 설정
  4. APK 파일 위치 또는 Release 링크
- **Private 저장소도 가능** → 공지되는 심사용 GitHub 계정을 Collaborator로 초대하고, 마감 전 접근 확인.
  개인 계정 저장소의 Collaborator는 쓰기 권한까지 받는 점에 주의.

> **이 저장소는 현재 Public입니다.** 아이디어가 정해지면 다른 팀에게 노출되므로 Private 전환을 고려하세요.
> Private이면 심사용 계정 초대가 필요합니다(계정은 공지 확인).

## 7. 팀 접수 · 수정 제출

- 팀원 **각자** 동의 여부·서명·날짜 작성. 대표자가 **팀원 전원을 CC**로 넣어 발송 (CC만으로 동의를 대신할 수 없음).
- 수정 제출: 마감 전, **처음 보낸 이메일 주소로** 다시 발송. 마지막 제출본이 최종.
- 수정 제출 제목: `[수정제출] [차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`
- 수정할 때도 **전체 자료 + 서명 동의서 전부 재첨부 + 팀원 전원 CC** (안 하면 유효 접수 아님).

## 8. 개발 환경 (요약)

- Android **API 28 이상**(minSdk), **Gradle 8.0 이상**, Java 또는 Kotlin.
- 사용 가능 SDK: Vehicle(차량 상태), FusedLocation(위치), NaviHelper(길 안내 연동), TextToSpeech · SpeechToText(음성).
  각 SDK의 제공 상태·사용 조건은 공식 문서 확인 → [sdk-reference.md](../02-pleos/sdk-reference.md)
- 에뮬레이터로 구동 검증 가능 → [dev-environment.md](../02-pleos/dev-environment.md)
- 가이드의 참고 예시: 음성 메모(STT), 안전운전 점수(Vehicle), 배달 기사 동선(NaviHelper) — **그대로 쓰면 창의성에서 불리**.

## 9. 숏폼 챌린지 (별도 50만 원 + 행사 초청)

- 30초~1분 **세로** 영상. 본인/팀 계정 **Instagram 릴스 또는 YouTube Shorts**에 게시.
- 해시태그 2~3개, **`#HMG차량용앱개발공모전` 필수** (제안: `#PleosAppMarket` `#HMG앱공모전`).
- 구성 예시: **Spot**(불편한 순간) → **Solve**(앱으로 해결) → **Scene**(사용 장면).
- 기간 10-21 ~ 11-15, 링크는 접수양식 8번.
- 블라인드: 개인 계정 대신 팀 계정 권장. → [demo-video-guide.md](../05-submission/demo-video-guide.md)

- 표절, 다른 공모전 수상작 → 심사 제외.
