# 사업성 숫자 만들기 (타깃 · MAU · Retention · 확대 계획)

심사 문구: "타깃 고객이 명확하고, 사용자 확보·지속 이용·확대 가능성 (**타깃 분석, 예상 MAU, Retention Rate, 확대 계획**)".
숫자 자체보다 **"어떤 가정으로 계산했는가"를 보여 주는 것**이 중요합니다. 모든 숫자에 가정과 출처를 붙입니다.

## 2. 퍼널로 MAU 추정하기

한 줄 산식:

```
MAU = 탑재 차량 수(해당 연도) × 앱 마켓 이용률 × 타깃 해당 비율 × 설치율 × 월간 활성률
```

| 단계 | 가정 예시 (반드시 우리 값으로 바꾸기) | 근거를 찾을 곳 |
|---|---|---|
| 탑재 차량 수 | 2027년 말 누적 N대 | 현대차·기아 월별 판매 실적(IR), 탑재 차종 발표 |
| 앱 마켓 이용률 | 차주 중 앱 마켓을 열어 보는 비율 a% | 유사 사례: 스마트폰 앱스토어 이용률, 테슬라·안드로이드 오토모티브 차주 행태 기사 |
| 타깃 해당 비율 | 예) 자녀 동승 가구 b%, 전기차 비중 c%, 법인차 비율 d% | 통계청(가구 구성), 국토교통부 자동차 등록 통계, 전기차 보급 통계 |
| 설치율 | 타깃 중 설치 e% | 앱 마켓 내 노출 위치·카테고리 경쟁 수준으로 보수적으로 |
| 월간 활성률 | 설치자 중 매달 쓰는 비율 f% | 이동 빈도(출퇴근 매일 / 주말 가족 이동) |

**보수 / 기준 / 낙관 3가지 시나리오**로 표를 만들고, 기획서에는 "기준" 값과 범위를 함께 씁니다.

## 3. Retention — "다시 쓸 이유"를 숫자로

- 앱이 붙는 **이동의 빈도**가 Retention의 상한입니다. 출퇴근(주 5회) > 주말 가족 이동(주 1~2회) > 장거리 여행(월 1회 이하).
- 차량 신호가 **알아서 앱을 불러오는 구조**(출발·도착·배터리·문 열림 등)면 사용자가 앱을 기억하지 않아도 다시 쓰게 됩니다.
- 쓸 지표 예시: D1 / D7 / D30 Retention, 주간 활성 이동 수(WAU 대비 이동 횟수), 기능별 사용 빈도.
- 가설 예시: "출퇴근 사용자의 D30 Retention 40% — 매일 출발 시 자동으로 뜨는 안내가 재방문을 만든다"
  → 근거: 유사 앱(내비·음악) 재사용 행태, 인터뷰에서 "매일 쓰겠다" 응답 비율.

## 4. 수익·지속 모델 선택지

| 모델 | 맞는 경우 | 주의 |
|---|---|---|
| 무료 + 제휴(충전·주차·휴게소·보험 등) | 위치·이동 맥락에서 제휴 전환이 자연스러울 때 | 광고성 알림 금지(Pleos 가이드) — 운전 중 광고 노출 불가 |
| 구독 | 매일 쓰는 고빈도 기능 | 차량 단위 vs 사용자 단위 결제 |
| B2B (법인·렌터카·공유차·물류) | 업무 이동, 다수 차량 관리 | 개인정보·위치정보 동의, 관리자 화면 필요 |
| OEM 기본 탑재 / 협업 | 차량 기능과 깊게 결합된 경우 | 수상작은 주최측 통상실시권·4개월 우선협상권 가능 |

## 5. 확대 계획 쓰는 순서

1. **차종 확대**: 더 뉴 그랜저 → 현대·기아·제네시스 전 차종 (2030년 약 2,000만 대 목표)
2. **지역 확대**: 국내 → Pleos Connect 탑재 해외 시장(예: 유럽 출시 차종). 지역별 주행 규제 차이 대응 ([driving-safety-and-ux.md](../02-pleos/driving-safety-and-ux.md))
3. **기능 확대**: Vehicle Control SDK·FusedLocation 등 제공 범위가 넓어지면 추가할 기능, Gleo 음성 연동
4. **고객 확대**: 개인 → 가족 공용 → 법인·공유차(B2B)
5. **데이터 확대**: (개인정보 동의를 전제로) 익명 집계 데이터로 서비스 개선
