# 아이디어 고르는 법

목표: **11-07(토)까지 아이디어 1개 확정.** 확정 기준은 "심사 4항목에서 이길 수 있고, 10일 안에 에뮬레이터에서 핵심 장면을 시연할 수 있는가"이다.

## 1단계 — 불편한 장면 모으기 (Spot)

한 장면 = 한 줄. 아래 형식으로 최소 15개를 모은다.

> **누가** · **언제/어디서** · **무엇이 불편한가** · **지금은 어떻게 버티나**
> 예) 초등생 둘을 태운 부모 · 고속도로 2시간째 · 뒷좌석이 지루해하고 싸움 · 휴대폰 영상을 쥐여 줌

찾을 곳
- 직접 경험, 가족·지인 인터뷰 (운전자 1명, 동승자 1명이라도)
- 자동차 커뮤니티 (보배드림, 클리앙 자동차 게시판, 차종 동호회), 앱 리뷰
- Pleos Connect 탑재 차량(신형 그랜저 등) 리뷰 영상의 댓글과 불만
- 공공·교통 데이터로 보이는 문제 (휴게소 혼잡, 충전소 대기, 졸음운전 사고 통계)

## 2단계 — 차량 데이터와 연결하기

장면마다 "**차가 알고 있는 것**"으로 해결할 수 있는지 본다. 아래 표는 SDK로 읽을 수 있는 신호와 떠올릴 수 있는 방향이다.
(정확한 API·권한·제공 상태: [sdk-reference.md](../02-pleos/sdk-reference.md), 에뮬레이터 시연 가능 여부: [emulator-and-virtual-console.md](../02-pleos/emulator-and-virtual-console.md))

| 차가 아는 것 | 어디서 | 떠올릴 수 있는 방향 (예시일 뿐) | 에뮬레이터 시연 |
|---|---|---|---|
| 주행 규제 on/off, 기어 P·R·N·D | AAOS CarUxRestrictions, GEAR_SELECTION | 출발·도착·정차 순간을 계기로 하는 기능, 주차 중에만 여는 상세 화면 | ✅ Virtual Console 기어 |
| 누적 주행거리, 트립 거리·시간, 주유 후 거리 | Vehicle SDK Odometer | 운행 기록, 이동량 기반 보상·리포트 | ✅ Odometer 카드 |
| 좌석 탑승, 안전벨트 체결, 도어 열림 | Vehicle SDK Seat · Door | 동승자·뒷좌석 케어, 하차 안전, 탑승 인원 맞춤 | ✅ Seat Occupancy, Door 카드 |
| EV 배터리 SOC, 전비·연비, 충전 상태 | Vehicle SDK EvBattery · Fuel | 충전 계획, 효율 코칭, 충전 대기 시간 활용 | ✅ Energy 카드 |
| 공조(온도·풍량·내기순환·열선), 실내 온도 | Vehicle SDK HVAC | 쾌적·건강, 계절 맞춤 | ✅ Climate 카드 |
| 방향지시등, 조향각, 브레이크, 크루즈 | Vehicle SDK TurnSignal · Steering · Brake · DrivingMode | 운전 습관, 주행 맥락 판단 | ✅ Motion·ADAS 카드 |
| 와이퍼, 조명(전조등·실내등) | Vehicle SDK Wiper · Light | 날씨·야간 맥락 | ✅ Convenience 카드 |
| 엔진오일·브레이크액·워셔액 경고 등 | Vehicle SDK Safety | 정비 알림 | ⚠️ 해당 카드 없음 (Telltale 카드는 앱에서 못 읽음) |
| 현재 위치, 목적지·남은 거리/시간·통행료, 경유지, TBT, 제한속도, 단속카메라 | NaviHelper | 경로·도착 시간 기반 콘텐츠, 경유지 추가 | ⚠️ 에뮬레이터 내비 응답 확인 필요 |
| 하이패스 카드 삽입·요금소 진입/진출 | Virtual Console ETCS 시나리오 | 톨게이트 이벤트 | ⚠️ 앱에서 읽는 API 확인 필요 |
| 사람의 말 | TTS · STT (on-device), Gleo | 화면 없이 대화하는 기능 | ✅ (마이크 설정 필요) |

**쓸 수 없거나 조심할 것**
- 차량 제어(Vehicle Control: 문·창문·시트·공조 조작) SDK는 "준비 중" → 핵심 기능으로 삼지 말 것
- Telltale(경고등)·타이어 공기압 리스너는 비공개 권한(PRIVATE_CAR_SAFETY) → 앱에서 못 씀
- POI(장소) 검색 API 없음 → 장소 데이터는 앱이 직접 가져야 함 (공공 API 등: [public-data-apis.md](../03-references/public-data-apis.md))
- 속도 리스너(VehicleSpeedListener)는 SDK 2.3.2에서 삭제 → AAOS PERF_VEHICLE_SPEED 사용
- 카메라·전화·SMS·일부 센서는 차량에서 제공되지 않거나 제한될 수 있음

## 3단계 — "폰으로도 되는데?" 시험 (차량특화성)

세 질문 중 **두 개 이상 "예"**여야 다음 단계로 간다.

1. 차량 데이터(위 표)가 없으면 핵심 기능이 성립하지 않는가?
2. 주행 중/정차 중을 구분해서 다르게 동작하는가? (주행 중에는 음성·최소 조작, 정차 중에는 풍부한 화면)
3. 운전자 말고 **동승자(뒷좌석 포함)**의 경험도 바뀌는가? (심사 문구에 "운전자 및 동승자" 명시)

## 4단계 — 채점표

각 항목 1~5점. 가중치는 심사 기준 + 우리 사정(10일, 2인, 에뮬레이터 시연)을 반영한 제안값이다.

| 아이디어 | 차량특화성 ×25 | 창의성 ×20 | 기술 활용성 ×20 | 사업성 ×15 | 10일 구현·시연 ×20 | 합계(100) | 비고 |
|---|---|---|---|---|---|---|---|
| (예) 아이디어 A | 4 | 3 | 4 | 3 | 5 | | |
| | | | | | | | |

합계 = Σ(점수 × 가중치) / 5. 동점이면 **"10일 구현·시연"이 높은 쪽**을 고른다.

점수 기준
- **차량특화성 5**: 차량 신호 2개 이상이 핵심 흐름을 움직이고, 주행/정차 UX가 다르다
- **창의성 5**: 공개된 다른 팀 주제·공식 예시·이전 수상작과 겹치지 않고, 장면 정의가 날카롭다
- **기술 활용성 5**: SDK 2~3개(예: Vehicle + NaviHelper + TTS/STT)가 장식이 아니라 핵심에 쓰인다
- **사업성 5**: 타깃이 분명하고 매일·매주 다시 쓸 이유(Retention)가 있으며, 수익·제휴 경로가 보인다
- **10일 구현·시연 5**: 필요한 API가 지금 "사용 가능"이고, Virtual Console로 장면을 그대로 재현할 수 있다

## 5단계 — 겹침 확인

- 공모전 가이드의 참고 예시: **음성 메모(STT), 안전운전 점수(Vehicle), 배달 기사 동선(NaviHelper)** → 그대로 쓰지 않기
- 이전 수상작(보도 기준, 원문 확인 권장): Pleos Connect 앱 아이디어 공모전 대상 "창밖동화"(지나가는 지역 이야기를 아이에게 생성), 현대차그룹 해커톤 수상작 "TaleSync"(차량용 대화형 오디오 이야기)
- 공개 저장소로 보이는 다른 참가팀 주제: [competitor-map.md](competitor-map.md) — 이야기·동화, 정비, 운전 습관, 충전, 장소 찾기, 운행일지 쪽이 붐빈다
- 표절·다른 공모전 수상작은 **심사 제외** 사유다. 남의 코드·문구·기획을 가져오지 않는다.

## 좋은 아이디어의 공통점 (심사 기준에서 거꾸로)

- **한 장면이 선명하다.** "고속도로 휴게소 10km 전, 뒷좌석 아이가 화장실을 찾을 때"처럼 시간·장소·사람이 보인다.
- **차가 먼저 말을 건다.** 사용자가 앱을 열기 전에 차량 신호(정차, 문 열림, 배터리 저하)가 계기가 된다.
- **주행 중에는 조용하고 짧다.** 화면 조작 없이 음성 한두 마디, 상세는 정차 후.
- **다시 쓸 이유가 있다.** 출퇴근, 주말 가족 이동처럼 반복되는 이동에 붙는다.
