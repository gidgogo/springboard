# 2인 팀 일정과 역할

> 기준일 2026-11-05(목). 접수 마감 **11-15(일) 23:59**, 1차 결과 11-23, **2차 PT 12-03~04**.
> 날짜는 목표이고, 매일 저녁 10분 점검에서 조정한다.

## 1. 전략 요약

1. **1차는 기획서로 20팀을 뽑고, 순위는 2차 PT 시연으로 정한다.** 1차는 가산점까지 챙겨 확실히 통과하고, 진짜 승부는 12-03~04 시연이다.
2. 가산점은 **단계별**이다. 기획서만 낸 팀 < 영상까지 낸 팀 < GitHub+동작하는 release APK까지 낸 팀.
   → 11-15까지 **핵심 기능 1개가 에뮬레이터에서 실제로 동작**하게 만들고, 영상과 APK를 같이 낸다.
3. 범위는 작게, 완성도는 높게. "핵심 장면 하나가 끝까지 매끄럽게 동작"이 "기능 다섯 개가 반쯤 동작"보다 낫다.

## 2. 역할 (제안)

두 사람 모두 코드를 만지되, **주 책임자**를 나눠 결정이 막히지 않게 한다.

| 영역 | A: 차량·플랫폼 담당 | B: 기획·화면 담당 |
|---|---|---|
| 기획서 | 5번(개발 계획·SDK 표) | **1~4, 6번 주 작성**, 최종 편집 |
| 코드 | `platform/*` (Car API·Pleos SDK 연동), 빌드·서명·CI | `ui/*` (주차/주행 화면), 문구·흐름 |
| 공통 로직 | `core/*` 함께 (주행 정책, 시나리오, 기능 로직) | |
| 에뮬레이터 | **Pleos 에뮬레이터 담당** (GPU 있는 사람) | 데모 모드로 화면 개발 |
| 사업성 | | **타깃·MAU·Retention 산식** |
| 산출물 | release APK, README 4항목 | 시연 영상, 숏폼, PT 자료 |
| 제출 | 이메일 발송 준비 | 서명·CC·블라인드 최종 점검 |

> GPU가 있는 노트북(권장 RTX 4060급, 최소 RTX 3060 6GB, 또는 Apple Silicon Mac)을 가진 사람이 A를 맡는다.
> 둘 다 없으면 오늘 바로 확보 방법을 찾는다 (학교 실습실 PC 등). 2차 PT는 **실제 동작 시연 필수**다.
