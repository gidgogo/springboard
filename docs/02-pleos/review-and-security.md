# App Market 심사 · 보안 · 개인정보 요점

> 출처: Pleos 문서 "App Review Guidelines"(콘텐츠 안전성 / 기능·성능 안정성 / 운전자 주의 분산 / 등록정보 / 개인정보·보안),
> "앱 보안 가이드", "보안 및 개인정보 보호를 고려한 설계"(document.pleos.ai, 2026-10).
>
> 공모전은 APK만 제출하므로 App Market 심사를 직접 받지는 않는다. 하지만 **2차 PT 심사위원은 이 기준을 아는 사람들**이고,
> 수상작은 App Market 탑재 준비를 지원받는다. 시연에서 걸릴 만한 것만 골라 정리했다.

## 1. 심사 5영역

| 영역 | 핵심 | 우리에게 해당하는 것 |
|---|---|---|
| 콘텐츠 안전성 | 선정·폭력·불쾌·유해 콘텐츠 금지, 미성년자 보호 | 키즈·동승자 기능이면 보호자 동의 흐름 |
| 기능·성능·안정성 | 설치·실행·사용 중 오류 없음, 더미 데이터·임시 파일 금지, 성능 저하 금지 | **데모 데이터는 debug 빌드에만** (이 저장소 구조), 0.25초 응답, 10초 실행 |
| 운전자 주의 분산 | Pleos UI Design Guide 준수, 미디어 앱은 주행 중 실행 불가 | [driving-safety-and-ux.md](driving-safety-and-ux.md) |
| 등록정보 | 메타데이터 정확, 개인정보·위치정보 쓰면 약관·처리방침 제출 | 기획서·앱 설명이 실제 기능과 같게 |
| 개인정보·보안 | 최소 수집, 명시적 동의, 철회 시 삭제, 악성 행위 금지 | 아래 2·3절 |

기능·성능 세부
- 앱 카테고리와 다른 기능을 넣으면 반려.
- 응답 0.25초(터치 → 터치 효과), 실행 10초, 콘텐츠 로드 10초, 버튼 반응 2초(넘으면 진행 표시).
- 백그라운드에서 돌아오면 마지막 상태 복원(수 시간 이상 지나면 기본 상태 가능).
- 사용자에게 재부팅이나 관계없는 시스템 설정 변경을 요구하지 않는다.
- **Vehicle SDK 권한은 App Market과 사전 협의·승인된 것만 선언 가능** (승인 안 된 권한이 있으면 심사 불가).
- 디스플레이 호환: 레터박스 없이 채우기(한 방향 미세 레터박스는 허용), 호환성 모드 실행 금지, 해상도 전환 시 상태·기능 유지.

## 2. 개인정보 (동의·최소 수집·삭제)

- 필요한 권한·데이터만. **왜 필요한지** 앱 안에서 알기 쉽게 알린다.
- 동의 화면: 모호하지 않게. **동의 버튼 말고 다른 행동(뒤로가기, 빈 곳 터치)을 동의로 보지 않는다.**
- 아동 개인정보는 법정대리인 동의.
- **사용자가 동의를 철회하면 즉시 사용을 멈추고 저장된 데이터를 삭제**한다.
- 위치정보를 저장·이용하면 위치정보사업 관련 신고 확인을 요청받을 수 있다.
- 차량은 여러 사람이 쓰는 기기: 운전자 교체 시 로그아웃·계정 전환 쉽게, 토큰은 Keystore 같은 안전한 저장소에.
- 차량 밖으로 나가는 데이터(텔레메트리): 차량 ID·사용자 ID 익명화/가명화 정책, **운전 중 행동 데이터를 마케팅에 쓰지 않기**.
- 로그에 개인정보가 들어가면 마스킹. VIN(차대번호)도 개인 식별에 쓰일 수 있으니 조심.

## 3. 보안 가이드 요점 (지키지 않으면 심사 통과 불가)

| 분야 | 해야 할 것 |
|---|---|
| 민감 데이터 저장 | 저장 위치와 상관없이 **앱 수준 암호화**(SQLite·SharedPreferences·캐시·파일). 임시 사본도 평문 금지 |
| 로그 | 배포 전 디버그 로그 끄기 또는 민감정보 마스킹 |
| 백업 | 쓰지 않는 자동 백업 끄기 (이 저장소: `android:allowBackup="false"`) |
| URL | **토큰·세션·비밀번호를 URL 경로·쿼리에 넣지 않기** (헤더로) |
| 암호화 | AES-GCM 등 검증된 방식, ECB 금지, MD5·SHA-1 금지(SHA-256), IV 재사용 금지, 안전한 난수, **키는 Android Keystore** |
| 통신 | HTTPS, **TLS 1.2 이상**(1.3 권장), 인증서 검증 우회 금지, 신뢰할 수 있는 서버만 |
| 컴포넌트 | 필요 없는 Activity/Service/Receiver/Provider는 `exported=false`. 민감정보를 암시적 브로드캐스트로 보내지 않기 |
| WebView | 로컬 파일 접근 최소화, JS 브리지는 필요할 때만, 신뢰할 수 없는 콘텐츠 격리 |
| 하드코딩 | **API 키·토큰·비밀 키를 소스·리소스·설정 파일에 넣지 않기** (공공 API 키 포함 → 아래 4절) |
| 배포 | **정식 배포 서명**, 디버깅·WebView 원격 디버깅 끄기, **버전을 올리지 않은 업데이트는 반려** |
| 라이브러리 | 알려진 취약점 확인, 패치된 버전 유지 |

## 4. 공공 API 키 같은 비밀값 다루기

- 저장소(특히 Public)에 키를 커밋하지 않는다. `.gitignore`에 `secrets.properties`, `.env`가 들어 있다.
- 로컬: `secrets.properties`(커밋 안 함)에 두고 `build.gradle.kts`에서 읽어 `BuildConfig`로 넘기는 방식이 간단하다.
  (단, APK 안에 들어간 키는 추출될 수 있다 → 진짜 비밀은 서버에서 호출하는 구조가 원칙)
- 이미 커밋했다면 키를 **즉시 재발급**하고 히스토리에서 지운다.

## 5. 제출 전 점검

- [ ] 매니페스트 권한이 실제 쓰는 것만 남았다
- [ ] release 빌드가 정식 서명되어 있고 `debuggable=false`
- [ ] 데모·테스트 데이터가 release 화면에 나오지 않는다
- [ ] 로그에 위치·VIN·음성 문장 원문 같은 개인정보가 찍히지 않는다 (필요하면 마스킹)
- [ ] 키·토큰이 저장소와 APK 문자열에 없다
- [ ] 동의가 필요한 데이터(위치·음성 등)는 앱 안에 이유와 동의 흐름이 있다
